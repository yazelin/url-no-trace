PRIVACY POLICY / CLEAN TRAIL

把資料邊界，
寫得和功能一樣清楚。

這份政策說明「無痕清理器｜Clean Trail」如何處理網址、規則、訂閱與剪貼簿。核心原則很簡單：清理工作在你的瀏覽器裡完成，Clean Trail 不建立你的瀏覽紀錄。

適用範圍

本政策適用於 Clean Trail 瀏覽器擴充功能、其公開原始碼，以及本專案的 GitHub Pages 產品介紹頁。Clean Trail 是一個開源、沒有帳號系統的本機優先工具。

使用這個擴充功能代表你了解：它會為了清理網址而讀取目前頁面的 URL，但不會把目前 URL 傳給 Clean Trail 的自有伺服器。

我們處理哪些資料

「處理」是指在你的瀏覽器中讀取、比對或保存必要資料；這不等於收集到我們的伺服器。Clean Trail 不收集、出售或分享你的瀏覽資料。

目前網址只在本機用來移除已知追蹤參數、更新網址列或產生複製預覽。
本機設定自訂規則、白名單、暫停狀態與訂閱狀態保存在瀏覽器的 chrome.storage.local。
剪貼簿只有你按下複製按鈕、右鍵複製或使用快捷鍵時，才會寫入清理後的網址。
同步結果外部清單的規則與同步時間保存在本機，用來顯示狀態和保留上一份有效版本。

我們不會做什麼

  • 不建立或上傳你的瀏覽歷程、搜尋紀錄、目前分頁清單或 URL 歷史。
  • 不使用分析工具、廣告追蹤、登入、個人化剖析或自有遙測後端。
  • 不把遠端訂閱內容當成程式執行，不使用 eval、new Function 或遠端 script 注入。

瀏覽器權限為什麼存在

以下是 Manifest V3 中每一項權限的實際用途。權限是為了完成使用者看得到的功能，不代表 Clean Trail 會把資料傳出。

storage
保存內建規則以外的自訂規則、白名單、暫停狀態與訂閱快取。
contextMenus
在連結的右鍵選單提供「複製無痕連結」。
alarms
每六小時觸發一次使用者已加入的規則清單同步。
tabs
取得目前分頁 URL，供 Popup、快捷鍵與右鍵複製功能使用。
scripting
在部分頁面無法使用一般內容腳本時，提供使用者主動要求的複製 fallback。
clipboardWrite
在使用者明確要求複製時，把清理後的 URL 寫入系統剪貼簿。
<all_urls>
讓同一套清理規則能在不同網站的頁面 URL 上運作；特殊的 chrome://、edge:// 和擴充功能頁仍受瀏覽器限制。

外部訂閱清單

訂閱不是預設開啟的功能。只有你在設定頁明確加入 HTTP(S) 規則網址後，Clean Trail 才會向該網址發出請求，讀取 JSON 或純文字規則；同步失敗時會保留上一份有效資料。

外部網站可以看到來自你的瀏覽器請求，並依照它自己的隱私政策記錄請求。這是訂閱來源的網路行為，不是 Clean Trail 上傳目前瀏覽網址。若不希望有這個連線，請不要加入該訂閱網址，或在設定頁移除它。

保存與刪除

本機設定會保留到你在設定頁按下「清除自訂設定」、移除相關項目、清除瀏覽器擴充功能資料，或解除安裝 Clean Trail。Clean Trail 沒有遠端帳號，因此沒有由我們代為保存的使用者資料。

解除安裝後，瀏覽器可能依自身機制處理擴充功能資料；若要在解除安裝前清除，可先從設定頁執行清除。

功能邊界

Clean Trail 主要改善網址分享、複製與網址列曝光。它在頁面載入後使用 history.replaceState 整理網址，不重新載入頁面，因此不能撤回網站在初始請求時可能已經收到的原始 URL。

未知參數、網址路徑與 # 片段預設保留，以降低破壞網站功能的風險。這不是網路層防追蹤器，也不宣稱能取代完整的內容或請求阻擋工具。
